PYTHIA · LOCAL CONNECTION GUIDE

Connect Google Calendar

Use a Google OAuth client that belongs to you. The client secret and refresh token stay on this Mac and must never be committed.

  1. In Google Cloud Console, select or create a project.
  2. Open APIs & Services → Library and enable Google Calendar API. Gmail is used only by the separate legacy analysis route.
  3. Set up the OAuth consent screen. For a personal test, choose External / Testing and add your Google account as a test user. Workspace policies may require admin approval.
  4. Create an OAuth client ID with application type Web application. Add the authorized redirect URI http://localhost:3000/auth/google/callback.
  5. In the project folder, copy .env.example to .env. Add the client ID and secret. Keep `.env` private; it is in `.gitignore`.
  6. Restart the server, open Connections, click Connect Google, and grant Calendar event access (the connection also requests Gmail read-only for the separate legacy analysis route).
  7. Open Calendar Breather and describe your preferences. PYTHIA checks the next seven days of availability, including all-day events, and can use the configured SecondStack Oracle to rank candidate times. Review and select break slots, then choose one-time or weekly recurrence (2, 4, 8, or 12 occurrences).

What PYTHIA accesses

  • Primary calendar events and all-day busy time for the next seven days when planning recovery breaks.
  • The recovery-break planning flow does not read Gmail or send event titles, descriptions, or attendees to the LLM. A separate legacy route can read recent Gmail snippets and estimates sentiment locally.
  • Calendar events are only created after you explicitly confirm the selected breaks. They are generic events without invitees. You can cancel a recurring series under Connections; later calendar changes may create conflicts.

The LLM can only rank locally generated times; it cannot create or change a time. If it is unavailable, a local planner still offers slots. No unattended scheduling jobs run. The app keeps OAuth tokens in the ignored `data/` folder with file permissions limited to your macOS user.
